# 个人实验项目的架构与开发边界

## 项目定位

这是个人使用的功能实验工具，以快速开发、切换数据来源和验证结果为主要目的。现有 TypeScript、Commander、SQLite、cron、Vitest 和官方 MCP SDK 构成单机应用，没有队列服务、工作流引擎或额外 Web 应用框架。

开发采用直接、易读的模块与函数；只在实际修改困难时拆分文件，已有的成熟依赖和标准库优先。测试重点是核心判断和外部接口契约，允许部分信号失败、查看错误后手动重跑，不要求完整的故障恢复或分布式执行保证。

## 当前模块分工

- `cli.ts`：参数、信号编排、入库、报告落盘及可选邮件；MCP 复用其入口。
- `sources.ts`、`breakout.ts`、`sitemaps.ts`：采集、差分和快照；`store.ts`：SQLite 线索及复盘结果。
- `usecases.ts`：证据、模型提词/筛选、相关查询、搜索量、Trends 与决策。
- `report.ts`：线索合并、名称评分和 Markdown 报告。
- `x.ts`：按用途显式切换数据源。Twitter AIO 为默认，Scrappa 账号采集、AIsa 搜索保留备选；失败不自动跨供应商请求。
- `scripts/notify-report.ts`：独立的 Telegram / 飞书报告投递。

保持现有结构便于直接运行和局部修改，没有为所有模块建立统一 Adapter、依赖注入容器或工作流抽象。Zod 用于 MCP 参数，远端数据另有局部校验；开放 JSON 仍使用 `Data`。

## 已有的轻量保护

- SQLite `Store.record()` 使用事务，快照用临时文件和 rename 原子替换。
- X 账号只有完成采集后才更新词表，分页停滞或超出预算会报错。
- 搜索本地验证正文、日期、点赞和回复，按 ID 去重；最多五页、获得十二条合格证据即可停止。
- sitemap 用旧 URL 的 Set 差分，逐条追加统计数据，不把整站数组展开为函数参数；当前仍完整解析 XML、在内存保留 URL 与词项。
- 每次 `loadConfig()` 重建内置及当前配置停用词，切换实验配置不会积累旧的自定义词。语言与停用词仍是进程级状态，适合当前单配置运行方式。

## 接受的限制

采集快照和后续线索入库不是共同事务，中间退出后重跑可能不再报告部分新候选。没有持久化步骤恢复、跨入口互斥或完整的逐请求费用账本；应避免手动任务与定时任务同时使用同一 state。用 `--state` 指向临时目录可以隔离实验，但首次运行会建立新基线。

单个信号失败会降级报告，其他信号继续；CLI 返回 0 表示报告流程完成，不代表所有接口成功。通知各渠道分别发送，重复执行可能重复投递。费用仅为可统计部分，AIO 套餐和模型费用不计入报告估算，中途异常也可能无法完整还原账单。

这些是当前个人实验工具的运行边界，不作为建立企业级基础设施的要求。实验时查看报告中的错误与数据来源，比无条件重跑所有收费请求更有用。

## 验证方式

`pnpm check` 运行格式、类型、测试及构建。核心判断保留业务基准和接口测试；配置切换用临时文件验证，sitemap 用 200,000 条旧 URL 的本地样本验证差分、词频及快照，无需真实网络。源码修改后 `pnpm build` 更新 cron 使用的 `dist`。
